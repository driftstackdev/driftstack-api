# Team RBAC

Driftstack supports multi-user teams: one owner-account plus zero or
more member-accounts joined to it via the `/v1/team/*` endpoints.
Each member uses their own login + their own dashboard sessions. API
keys remain account-scoped (shared across the team) and admin-gated.

> **Status (V-298c — May 2026):** invite + accept + list + remove
> shipped. The auth path itself does not yet honor team membership —
> accepted members can sign in but the membership grants no implicit
> permissions on the owner's resources until V-298d ships. Use the
> endpoints today to record team relationships; the permission lift
> lands next.

## Concepts

- **Owner account.** The account that pays the subscription. Shows up
  as `owner_account_id` on every membership and invite.
- **Member account.** A separate `accounts` row (own login, own
  email) joined to the owner via `team_members`. Cascade-delete on
  either side removes the membership.
- **Invite.** A pending double-opt-in record in `team_invites`.
  Generated by the owner; consumed by the invitee. Token-hashed at
  rest (sha256), 7-day expiry.
- **Role.** `member` (default) or `admin`. The role is recorded
  today; permission semantics ship with V-298d.

## Invite a team member

`POST /v1/team/invites` — sends an email with a 7-day accept link to
the invitee.

Request:

```json
{ "email": "alice@example.com", "role": "member" }
```

Response (202):

```json
{ "message": "Invite sent. The invitee can accept via the email link." }
```

The invitee receives an email containing a token URL. They sign up
on Driftstack first if they don't already have an account, then
accept.

## List pending invites

`GET /v1/team/invites` — pending (unaccepted, unexpired) invites for
the calling owner.

```json
{
  "data": [
    {
      "id": "inv_…",
      "owner_account_id": "acc_…",
      "invitee_email": "alice@example.com",
      "role": "member",
      "expires_at": "2026-05-15T10:00:00Z",
      "invited_by_account_id": "acc_…",
      "accepted_at": null,
      "created_at": "2026-05-08T10:00:00Z"
    }
  ]
}
```

## Accept an invite

`POST /v1/team/invites/accept` — invitee calls this after signing in
to their own Driftstack account.

Request:

```json
{ "token": "<token-from-email>" }
```

Response (200):

```json
{
  "membership": {
    "id": "mem_…",
    "owner_account_id": "acc_…",
    "member_account_id": "acc_…",
    "member_email": "alice@example.com",
    "role": "member",
    "invited_at": "2026-05-08T10:00:00Z",
    "accepted_at": "2026-05-08T10:05:00Z",
    "invited_by_account_id": "acc_…"
  }
}
```

The accepting account's email MUST match the invitee email — server
returns 409 Conflict otherwise. This prevents accidentally accepting
an invite addressed to someone else even if they share the URL.

## List members

`GET /v1/team/members` — confirmed memberships for the calling owner.

## Remove a member

`DELETE /v1/team/members/:id` — owner-scoped. 404 if the membership
isn't owned by the calling account.

## SDK examples

**TypeScript:**

```ts
await client.team.invite('alice@example.com', { role: 'admin' });
const members = await client.team.listMembers();
await client.team.acceptInvite(tokenFromEmail);
await client.team.removeMember('mem_…');
```

**Python:**

```python
client.team.invite("alice@example.com", role="admin")
members = client.team.list_members()
client.team.accept_invite(token_from_email)
client.team.remove_member("mem_…")
```

**Go:**

```go
client.Team.Invite(ctx, &driftstack.TeamInviteRequest{
    Email: "alice@example.com",
    Role:  driftstack.TeamRoleAdmin,
})
members, _ := client.Team.ListMembers(ctx)
client.Team.AcceptInvite(ctx, tokenFromEmail)
client.Team.RemoveMember(ctx, "mem_…")
```

## Audit log

Every team mutation writes an entry to the customer audit log
(`/v1/account/audit-log`):

| Action                 | Fires when                                 |
| ---------------------- | ------------------------------------------ |
| `team.member_invited`  | owner calls POST /v1/team/invites          |
| `team.invite_accepted` | invitee calls POST /v1/team/invites/accept |
| `team.member_removed`  | owner calls DELETE /v1/team/members/:id    |

Use the audit-log export (V-297) to download the team history at
any time:

```bash
curl -H "Authorization: Bearer $DRIFTSTACK_API_KEY" \
  "https://api.driftstack.dev/v1/account/audit-log/export?format=csv" \
  > team-history.csv
```

## Next steps

- **V-298d** wires the auth path so that members acting as the owner
  can read/write the owner's resources per their role. Until that
  ships, accepted memberships are purely informational.
- **Privacy / DPA**: a member is a separate Data Subject from the
  owner. Their account email is processed under Privacy §3.1 (Account
  data) on the same legal basis as any other Customer contact.
